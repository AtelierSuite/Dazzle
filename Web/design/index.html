Rules

These are enforced by lint.mjs across everything in Web/.

System font only

Every piece of interface text uses the operating system's sans-serif through --ds-font. No web fonts and no monospace, except the code editor's code. Pages keep the document's own fonts.

Default cursor

Buttons, tabs, menus and controls keep the arrow cursor. The pointing hand appears only on underlined text links with an href.

No chips

Choices are made with segmented controls, pop-up buttons, checkboxes or lists. No pill-shaped tags, filters or token fields.

No eyebrow text

A heading stands on its own. No small label stacked above a title to categorise it.

No all caps

Text is never transformed to capitals or small caps. Strings appear exactly as written in the string catalogues.

No wide tracking

Letter-spacing is always zero. Numbers line up with tabular figures, not monospace.

No selectable UI text

Labels, headings, menus and messages can't be selected. Only text fields, editable regions and document content can.

No draggable UI images

Icons, images and other UI media never start a drag. Only objects the user moves on purpose are draggable.

Square buttons

Every button has square corners, including icon, segmented, help and menu-bar buttons. Only checkboxes, radios, switches and sliders are rounded.

No fingernail strips

No coloured bar along one edge of a card, row, tab or notification. Selection and status fill the whole surface.

Colour

Carbon White theme in light appearance, Gray 100 in dark. Switch the appearance at the top of the page to compare.

Type

Carbon's productive scale set in the system font. Weights are 400 and 600 only.

Buttons

Push buttons, borderless toolbar buttons and the help button. The default (Return) button is the only one filled with the accent colour in a view.

Selection controls

Segmented controls replace tabs and chips. Pop-up buttons are native selects, so the operating system draws their menus.

Text fields

Carbon fields: a filled surface with a neutral one-pixel underline and an inset focus outline on all four sides.

Menus and popovers

Menus follow NSMenu: a checkmark column, title, keyboard shortcut in the system font, and a submenu arrow. Open menus always fit the window: they flip above or to the other side at an edge, scroll when taller than the window, and ellipsise titles when narrower. Popovers anchor to the control that opened them.
